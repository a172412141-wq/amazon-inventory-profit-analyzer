# 业务规则

本文件描述当前代码所实现的经营判断口径。阈值以 `config/thresholds.yaml` 为准；若文档和代码冲突，应记录差异并先用测试确认实际行为。

## 经营原则

1. 现金流健康优先于短期利润。
2. 良性周转优先于短期高毛利。
3. 高毛利但慢周转不自动等于优质 SKU。
4. 先排除不能补货的 SKU，再判断必须补货的 SKU。
5. 品线诊断优先序为：周转 > 规模 > 毛利润 > 毛利率。
6. 报告层的建议不能覆盖系统 `final_action` 和 `priority`。

## 库存口径

- 动作与分类优先使用 `available_stock_days`。
- `available_stock_days = available_stock_qty / (sales_7d_units / 7)`。
- 无可售库存字段时，`available_stock_qty` 回退为 `max(total_supply_qty - inbound_qty, 0)`。
- 有库存但 7 天销量为 0 时，可售库存天数记为正无穷，按无销量压货处理。
- 主要区间：
  - `< 14` 天：严重缺货风险。
  - `14-30` 天：即将断货。
  - `30-60` 天：健康库存。
  - `61-90` 天：加急周转。
  - `91-180` 天：红线库存，P0 停补/处理周转。
  - `> 180` 天：超红线，P0 清货。

## SKU 主动作

- 每个 SKU 只有一个 `final_action`、一个系统 `priority` 和一段 `reason`。
- 库存红线和无销量压货先于利润、广告与补货建议。
- 毛利润正负以 `order_gross_profit` 判断；毛利率用于分层和广告安全线。
- 广告有花费无销售，或 `ACOS >= order_gross_margin`，视为广告异常。
- `recommended_replenishment_qty > 0` 不能单独触发补货；库存、毛利润和广告条件必须允许。
- 当前动作集合和精确顺序由 `modules/recommendations.py` 定义。

## 毛利率分层

- `<= 0%`：亏损。
- `0%-8%`：低毛利率水平。
- `8%-15%`：中毛利率水平。
- `>= 15%`：高毛利率水平。

边界值和实际阈值以配置文件及测试为准。

## SKU 经营角色

角色与主动作相互独立，最终角色互斥，按以下优先级选择：

1. 引流 SKU：广告花费占父体总广告花费 `> 35%`。
2. 主力 SKU：日均销量高于父体内子 SKU 日均销量算术平均，且毛利率高于父体毛利率。
3. 利润 SKU：父体毛利率为正，且 SKU 毛利率至少为父体毛利率的 `1.5` 倍。
4. 低效异常 SKU：未命中以上条件。

父体毛利率按父体毛利润合计除以销售额合计计算；销售额优先使用 7 天销售额，合计无效时回退 14 天销售额。

## 广告和转化指标

- `ACOS = ad_spend / ad_sales`。
- 页面默认按 7 天口径展示销售、销量和 ACOAS，可用快速周期按钮切换到 14 天。
- `ACOAS = ad_spend / 当前周期 total_sales_amount`；总览、父体、SPU、品线和品线诊断都在筛选后的数据范围内重新汇总，且销售额分母必须与当前周期一致。
- `CPC = ad_spend / ad_clicks`。
- `CTR = ad_clicks / ad_impressions`。
- `ad_cvr = ad_orders / ad_clicks`。
- `cvr` 优先原表值，否则使用 14 天销量/14 天会话数，再回退 7 天口径。
- `ad_order_share = ad_orders / total_orders`；总订单无有效值时回退 14 天销量。

## 父体、SPU 和品线

- 聚合数量和金额字段采用求和。
- 聚合毛利率为毛利润合计除以销售额合计，不取子项毛利率算术平均。
- 加权库存天数按聚合可售库存除以聚合 7 天日均销量计算。
- 父体结构异常关注热卖缺货、滞销压货、广告错配和高销量亏损变体。

## Fang 品线诊断边界

- 每次只诊断一条品线。
- 输出数据可信度、核心指标、关系诊断、角色结构、问题 SKU、机会 SKU 和 ToDo。
- 原因等级只能表达当前证据强度，不应把相关关系描述为确定因果。
- 缺少时间窗口、历史趋势、利润成本口径或同类样本时，必须展示缺失信息和验证动作。
- 广告花费或点击未达到暂定可靠门槛时，Fang 报告不得把高 ACOAS 定义为品线核心矛盾；默认门槛为花费 `20`、点击 `20`，配置位于 `thresholds.yaml`，当前状态为 provisional。
- 广告样本不足只降低 Fang 报告结论及报告优先级，不改写系统 `final_action` 或 `priority`。
- ToDo 应保留系统 `final_action` 与系统 `priority`，报告优先级不得替代它们。
