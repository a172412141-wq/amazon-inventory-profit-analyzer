# 决策记录

本文件记录需要长期保留的重要技术与业务决策。状态可为“采用”“待确认”或“废弃”。

## D-001：以内层应用目录作为项目仓库

- 日期：2026-06-18
- 状态：采用
- 决策：`amazon-inventory-profit-analyzer/` 是真实项目根目录；外层 `New project/` 仓库不作为本项目状态、提交和发布依据。
- 原因：内层仓库有完整提交历史并连接 `origin`，外层只有一个旧快照提交，会产生大量误导性差异。
- 后续：长期应评估是否移除或重新定义外层仓库，但未经明确授权不得改动其 Git 元数据。

## D-002：SKU 角色与系统动作保持正交

- 日期：既有设计，2026-06-18 补录
- 状态：采用
- 决策：`sku_role` 表达 SKU 在父体内的经营角色；`final_action` 表达当前应执行的动作。二者互不覆盖。
- 原因：一个 SKU 可以是主力或利润角色，同时因为缺货、压货或广告异常需要不同即时动作。

## D-003：库存与现金流优先

- 日期：既有设计，2026-06-18 补录
- 状态：采用
- 决策：库存红线、无销量压货和现金流风险优先于高毛利及原表补货建议。
- 影响：高毛利 SKU 在 90 天以上库存时仍可能停补或清货。

## D-004：父体与聚合毛利率采用加权口径

- 日期：2026-06-11 前后实施，2026-06-18 补录
- 状态：采用
- 决策：聚合毛利率按毛利润合计除以销售额合计计算，不取 SKU 毛利率算术平均。
- 原因：算术平均会忽略 SKU 销售规模，不能反映父体、SPU 或品线的真实利润贡献。

## D-005：品线诊断是只读报告层

- 日期：2026-06-16 起实施
- 状态：采用
- 决策：Fang 品线诊断读取完整分析结果，生成可信度、关系诊断和 ToDo，但不得修改原数据、`sku_role`、`final_action` 或系统 `priority`。
- 原因：避免报告推断污染底层确定性规则，并保留系统动作的可审计性。

## D-006：数据不足时区分事实与假设

- 日期：2026-06-17 起实施
- 状态：采用，但实现待完善
- 决策：诊断使用“已确认原因 / 高概率原因 / 待验证假设 / 无法判断”表达证据强度，并输出缺失数据与验证动作。

## D-008：标准测试入口

- 日期：2026-06-18
- 状态：采用
- 决策：使用 `.venv/bin/python -m pytest -q`。
- 原因：当前环境直接运行 `.venv/bin/pytest` 时可能缺失项目根目录导入路径，而模块方式能稳定导入 `app` 和 `modules`。
