# 决策记录

本文件记录需要长期保留的重要技术与业务决策。状态可为“采用”“待确认”或“废弃”。

## D-001：以内层应用目录作为项目仓库

- 日期：2026-06-18
- 状态：采用
- 决策：`amazon-inventory-profit-analyzer/` 是真实项目根目录；外层 `New project/` 仓库不作为本项目状态、提交和发布依据。
- 原因：内层仓库有完整提交历史并连接 `origin`，外层只有一个旧快照提交，会产生大量误导性差异。
- 后续：长期应评估是否移除或重新定义外层仓库，但未经明确授权不得改动其 Git 元数据。

## D-002：SKU 角色与系统动作保持正交

- 日期：既有设计，2026-06-18 补录
- 状态：采用
- 决策：`sku_role` 表达 SKU 在父体内的经营角色；`final_action` 表达当前应执行的动作。二者互不覆盖。
- 原因：一个 SKU 可以是主力或利润角色，同时因为缺货、压货或广告异常需要不同即时动作。

## D-003：库存与现金流优先

- 日期：既有设计，2026-06-18 补录
- 状态：采用
- 决策：库存红线、无销量压货和现金流风险优先于高毛利及原表补货建议。
- 影响：高毛利 SKU 在 90 天以上库存时仍可能停补或清货。

## D-004：父体与聚合毛利率采用加权口径

- 日期：2026-06-11 前后实施，2026-06-18 补录
- 状态：采用
- 决策：聚合毛利率按毛利润合计除以销售额合计计算，不取 SKU 毛利率算术平均。
- 原因：算术平均会忽略 SKU 销售规模，不能反映父体、SPU 或品线的真实利润贡献。

## D-005：品线诊断是只读报告层

- 日期：2026-06-16 起实施
- 状态：采用
- 决策：Fang 品线诊断读取完整分析结果，生成可信度、关系诊断和 ToDo，但不得修改原数据、`sku_role`、`final_action` 或系统 `priority`。
- 原因：避免报告推断污染底层确定性规则，并保留系统动作的可审计性。

## D-006：数据不足时区分事实与假设

- 日期：2026-06-17 起实施
- 状态：采用
- 决策：诊断使用“已确认原因 / 高概率原因 / 待验证假设 / 无法判断”表达证据强度，并输出缺失数据与验证动作。
- 实现状态：完整率已结合 `_missing_` 标记，避免把清洗补零后的缺失值当作已提供字段；各关系规则的证据最低要求仍按 `docs/fang-rule-mapping.md` 逐条补齐。

## D-008：标准测试入口

- 日期：2026-06-18
- 状态：采用
- 决策：使用 `.venv/bin/python -m pytest -q`。
- 原因：当前环境直接运行 `.venv/bin/pytest` 时可能缺失项目根目录导入路径，而模块方式能稳定导入 `app` 和 `modules`。

## D-009：界面以经营决策层级组织

- 日期：2026-06-18
- 状态：采用
- 决策：首页使用业务产品名和三步使用引导；总览只突出利润、周转、库存风险和行动队列，完整指标放入展开区；各分析栏目补充用途说明。
- 原因：原页面使用工程仓库名作为标题，并平铺大量指标和长导航，用户难以判断先看什么以及下一步该做什么。
- 约束：仅调整展示层和文案，不修改指标公式、筛选字段、SKU 角色、系统动作或优先级。

## D-010：Fang 原型按规则吸收，不作为第二套引擎整体接入

- 日期：2026-06-18
- 状态：采用
- 规范来源：《Fang经营关系诊断模型 V0.1》，SHA-256 `5f793dfc0a77a6c8e4d3d06f51b84e94e50887373282edf92e439021672315bf`。
- 决策：当前生产入口继续使用 `modules/product_line_diagnosis.py::build_product_line_diagnosis`。未跟踪的 `fang_diagnosis/` 仅作为规则治理、证据结构和数据校验的设计原型，不整体接入、不形成并行运行引擎。
- 原因：生产实现已有页面、ToDo、汇报层和回归测试；原型虽具备规则 ID、证据对象和版本状态，但没有统一入口、完整行动计划、测试或现有管线集成。整体替换会产生两套业务判断和规则漂移。
- 合并方式：按“规则治理层 → 证据层 → 数据校验层 → 关系规则层 → 阶段与实验层”逐条迁移，每条规则先建立来源、边界、阈值状态和回归测试。
- 阈值约束：V0.1 文档明确说明阈值尚未充分量化；除数学恒等边界外，没有案例记录的原型阈值不得标为稳定。生产 `config/thresholds.yaml` 不被原型配置自动覆盖。
- 审计清单：见 `docs/fang-rule-mapping.md`。

## D-011：广告样本不足只降级 Fang 报告结论

- 日期：2026-06-18
- 状态：采用
- 决策：`FANG_REL_008` 只在 Fang 品线报告层判断广告样本可靠性。花费或点击未达到暂定门槛时，广告关系降为“待验证假设”与 P3，不把高 ACOAS 定义为品线核心矛盾；系统 `final_action` 和 `priority` 保持不变。
- 暂定门槛：广告花费 `>= 20` 且广告点击 `>= 20` 才视为达到报告诊断样本边界；配置位于 `config/thresholds.yaml`，状态为 provisional。
- 原因：规范原文要求数据口径未确认前不得形成确定性结论，并明确 V0.1 阈值尚未量化；20/20 来自设计原型，没有三个不同业务案例的验证记录。
- 后续：建立规则执行快照并记录案例数量；若未来希望样本可靠性改变系统“控广告”动作，必须另行评审动作规则和边界测试，不能由报告层覆盖。

## D-012：页面周期口径默认 7 天

- 日期：2026-07-08
- 状态：采用
- 决策：页面默认按 7 天展示销售额、销量、日均和 ACOAS，并提供 7 天/14 天快速周期切换。
- 原因：经营决策优先看最近 7 天变化，同时保留 14 天视角用于平滑短期波动。
- 影响：总览、父体、SPU、品线和品线诊断的 ACOAS 均按筛选后的当前周期销售额作为分母；SKU 角色、系统 `final_action` 和系统 `priority` 不因页面周期切换而改写。
